## Corrections to the unfinished draft

1. Weight-1 entries must not silently disappear from the denominator. The Python calculator requires an explicit assumption when they occur. The browser explorer requires explicit opt-in for every published-weight model.
2. Three-option Desecration cannot be assumed to sample uniformly from every listed row. The previous ~61% claim is not published as an in-game probability.
3. Fracturing requires at least four modifiers. The previous amulet route built only three. A wrong fracture cannot be retried on the same base as if it had reset.
4. A side restriction does not guarantee a modifier family. Perfect Exalted's modifier-level floor is not a T1 guarantee.
5. Kurgal physical and ordinary local physical on two-hand maces share `LocalPhysicalDamagePercent` in the snapshot. They are alternatives.
6. A fixed “100 div minimum” is not a guarantee or stable market rule. The UI instead models explicit per-attempt cost, one-time cost, spending cap, mean cost and a 90% success budget.
7. The old amulet checklist under Totems & Mana now links to the single maintained Crafting workflow. Legacy completion keys remain in storage but are not assigned to changed steps.

## What the model means

The optional weight explorer divides a target's published weight by the eligible published weight sum after filtering **one addition** by item level, currency floor, available sides and blocked families. It includes weight 1. It does not model the removal part of Chaos, quality/catalyst effects, special base tags, Genesis, multi-step completion or Desecration sampling. Ordinary class pools are not guaranteed to capture every special-base exception.

Tier labels in the UI are inferred within each normalized modifier text line, ordered by modifier level. They are not imported authoritative tier identifiers. “Level eligible” does not imply full eligibility on a particular existing item.

The cost simulator models independent attempts at a fixed state:

- Expected attempts: `1 / p`.
- Success in `N` attempts: `1 - (1 - p)^N`.
- Attempts fitting the budget: `max(0, floor((budget - initial) / perAttempt))`.
- 90% budget: `initial + ceil(log(0.1) / log(1-p)) * perAttempt` (special case for p=1).

If failure loses the base, include replacement in `perAttempt`. If success completes one stage, the cost describes that stage only. Missing costs stay unknown. The browser uses `log1p`/`expm1` for small probabilities and validates inputs.

## Maintenance

Run `python tools/build_all.py` from any directory. This rebuild uses local snapshots and does not fetch prices. To refresh data, preserve the response's source, league, timestamp and version alongside it; do not infer these from filesystem modification times.

Source files for UI: `shared/craft.js`, `shared/weights.js`, `shared/guide.js`, `shared/guide.css`. `shared/craft-data.js` is generated by `tools/craft/build_data.py`. Source templates stay in `tools/`; the four build HTML files and both landing pages are generated outputs.
